# 레퍼런스 분석과 적용 기준

## 이미지에서 실제로 보이는 특징

- 상단의 밝고 얇은 바와, 그 아래 거의 순수한 검정 무대가 강하게 대비된다.
- 웜그레이 구름 실루엣이 좌우와 하단을 크게 차지하고 중앙에 검은 여백을 남긴다.
- 얇은 방사선, 윤곽선, 네 갈래 별이 하나의 시각 언어를 만든다.
- 중앙 오브젝트는 겹친 윤곽과 기울어진 판으로 공간감을 만든다. 그라데이션이나 무거운 그림자가 중심 표현 수단이 아니다.
- 민트는 작은 주요 버튼과 소수의 강조에 한정된다.
- 화면 상단 awwwards 메뉴와 중앙의 원형 심사 점수는 참고 사이트의 UI다. 제품에 AI 점수로 옮기지 않는다.

## 이전 결과에서 바꾸는 것

- 녹색 기운의 패널과 같은 둥근 카드를 반복한 구성 제거.
- 장식을 작은 랜딩 카드 안에 가두지 않고, 모든 화면에 동일한 여백·색면·윤곽선·타이포 규칙 적용.
- 폼, 문서, 표, 분석, 의사결정을 서로 다른 정보 구조로 설계.
- 사이드바의 모든 항목을 알약 버튼으로 만드는 대신, 명확한 현재 위치와 얇은 구분선 사용.
- 본문 15px 이상, 작은 보조 정보 12px 이상. 실제 입력 요소는 가용 폭 전체를 사용.

## 공통 규칙

- 색상: 검정 #080808 / 종이 #EEECE5 / 웜그레이 #A6A397 / 민트 #53CBB7 / 선 #42423E.
- 작업 공간: 밝은 헤더, 검은 사이드바, 검은 여백 위의 종이색 작업 영역.
- 타이포: 큰 제목 52–76px, 섹션 제목 24–32px, 문서 본문 16px. 화면의 목적에 맞춰 위계 조절.
- 모티프: 랜딩에는 큰 구름·방사선, 작업 화면에는 작은 궤도 또는 별 모티프, 빈 상태에는 여백이 큰 윤곽선 오브젝트.
- 강조: 민트는 주 행동과 현재 위치. 증거/판정은 텍스트와 선, 제한적인 상태 색상으로 표현.
- 형태: 종이 작업판은 0–4px 모서리, 주 버튼만 둥근 모서리, 이미지 오브젝트는 20px.
- 한 화면에 주요 행동은 하나. 증거 배지·잠정·예시 표시는 계속 유지.

## 화면별 구조

| 화면 | 적용 방식 |
|---|---|
| landing | 검은 무대, 중앙 헤드라인, 양옆 구름, 떠 있는 윤곽선 카드 |
| auth | 검은 브랜드 영역과 종이색 로그인 폼의 분할 |
| projects | 큰 제목 아래 가로 프로젝트 카드와 얇은 활동 목록 |
| project_create | 단계 표시 + 종이색 입력판 + 오른쪽 안내 |
| dashboard | 다음 행동을 큰 웜그레이 판으로 강조, 하단 위험 가설과 검증 흐름 |
| business_model | 실제 Lean Canvas 구조의 격자와 버전 도구 |
| diagnosis | 수요×가능성 사분면 + 근거 패널 + 비용/대체 위험 별도 영역 |
| hypotheses | 우선순위 테이블 + 선택 가설의 상세 패널 |
| proposal | 실제 문서처럼 보이는 기획서 + 우측 잠금·내보내기 컨트롤 |
| results | 단계별 제출 폼 + 오른쪽 증거 체크리스트 |
| verdict | 큰 판정 문구 + 근거 행 + 다음 행동 |
| decision | 서비스 권고와 팀의 선택을 분리한 4방향 결정판 |
| post_launch | 가설별 지표 표 + 증거가 되돌아오는 경로 |
| data_connection | 도구별 연결 행 + 동기화 정보 |
| project_settings | 설정 섹션과 팀원 테이블 |
| archive | 보관 이유 중심의 간결한 기록 목록 |

## 상태

현재 이 설계는 로컬 검수용 재설계안이다. Figma Starter MCP 호출 한도로 기존 Figma 파일에는 아직 적용되지 않았다. 기존 handoff.json의 노드 ID는 기존 파일에 대한 것으로 유지한다.
